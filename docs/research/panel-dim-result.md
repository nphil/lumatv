# Panel dim: the saver and an idle Home dim the panel's own light

Built and host-tested; not run on the TV. Switch: `theme.oledcare.panelDim` (Settings › System › OLED care › LumaTV panel care › Dim with the panel), **on in the shipped theme**. `panelDimStepSec` (2, 1 to 60) is the least time between two writes of a ramp. The compositor reads the theme within 2 s.

The dim is LG's picture setting "OLED pixel brightness" (`picture.backlight`, 0 to 100, per picture mode), written through `luna://com.webos.service.settings/setSystemSettings` exactly as Settings › Picture writes it (`rustui/ui/src/host/sio.rs`). A frame drawn at full brightness can go to the display plane whole (`Plan::sole_fullscreen` needs every item at 1.0), so a dimmed screen is not composed. The GPU multiplier of `oledcare` (`u_dim`) stays for what the panel cannot do: one box (`boxDim`), one app (`appDim`).

## What it does

| Part | Rule |
|---|---|
| Who asks | The screen, as a fraction of the user's value (`want`, 1 = nothing). The Rust shell's saver: its own dim curve (`saverState.level`, 1 down to `dimTo`, over `dimOverMin`), read only while the saver reports `saverState.carry`. Idle Home: the care's ease (`Care::home_want`, `dimAfterMin`, `dimOverMin`, `dimTo`), only with `oledcare.enabled`. The QML saver has no level and keeps dimming its own picture. |
| Handoff | The compositor tells the Rust client `paneldim {carry}` (true while the switch is on, the bridge is connected and no failure is latched). With `carry` the saver draws its block at its first brightness (`view.level` 1) and reports `level`; Home is drawn at `dim` 1 (`Care::dim(0)`) while its ease runs on as `home_want`. Without it both dim their own picture as before. |
| Baseline | The first time a dim is wanted, `getSystemSettings {category: picture, keys: [backlight]}` is read: the value and its dimension (picture mode, input, dynamic range). |
| Ramp | One unit a write, at most one write per `panelDimStepSec`, toward `round(value x want)`, never below 10 (`FLOOR`) and never above the user's value. The baseline's dimension goes with each write. Idle Home at 0.85 of 80 is 12 writes over the care's 10 minutes; the saver at 0.4 is 48 writes over 20 minutes. |
| Put back | The user's exact value, in one write (not a ramp): key or pointer (`State::care_input`), a screen that wants to be bright (saver ends, Home touched, app in front: `want` rises), a video (`Plan::video` or a hole), standby (`power.rendering` false), the switch turned off, a refused write, SIGTERM, SIGINT and `ctl quit`. A read goes first (see user's change) except for standby and exit. |
| Never | While a video plays; in any HDR or Dolby Vision dimension (`dynamicRange` other than `sdr`, or a picture mode with `hdr` or `dolby` in it): the baseline is read and refused, no write, no GPU dim either (Home is not shown under HDR video); a dim that arrives under the panel (`poll` sees another dimension) is put back to the dimension it was taken from, hurried. Not within 3 s of a key. |
| User's change | While dimmed the setting is read every 20 s; before any put back it is read. A value that is neither the last written nor the user's was changed by someone else (a phone, voice, HA): it is left alone, the journal goes, no dim begins for 5 minutes. |
| Journal | `paneldim.json` in the data directory: `{orig, written, dimension, pid, at}`, written before the first write below the user's value and with each write, removed when the user's value is back. |
| Crash | A compositor that starts with a journal reads the setting (with the journal's dimension) and writes `orig` when the value is still `written`; otherwise drops it. The helper's `paneldim` thread looks every 15 s: a journal whose pid is no running `lumatv-compositor` and that is over 30 s old gets the same treatment (`helper/app/src/paneldim.rs`), so a compositor that stays dead does not leave the panel dim. |
| Failure | No bridge, an unreadable baseline, an answer without a dimension or a refused first write: off for 10 minutes (`carries()` false, the shell is told, the GPU dim and the saver's own dim do the work). A refused write in the middle of a dim puts the value back and does the same. A refused put back is tried again after 1, 2, 4 ... 30 s with the journal kept. |
| Dimension | A call names `{pictureMode, input}` only (`paneldim::call_dimension`): the service refuses a read whose dimension also names `dynamicRange` ("no result from DB", round 20). The range is read from the baseline's answer for the HDR rule and compared with what a later read names, never sent. |
| Refresh guard | Only `com.webos.service.settings` is called. Nothing touches the power state or wakes the TV, so LG's standby panel refresh is not interfered with. The standby put back is a settings write sent as `PreparePowerOff` takes effect. |

`SIGTERM` and `SIGINT` were not handled before (the process ended on the spot). They now end the loop at its next pass so the put back runs and its answer is waited for (800 ms at most); `SIGALRM` after 3 s ends a wedged loop as `SIGTERM` did before.

`ctl status` `oledcare.panelDim`: `enabled`, `carries`, `dimmed`, `orig`, `written`, `inFlight`, `want`, `block`, `hdr`, `latchedSec`, `writes`, `reads`, `restores`, `failures`, `lastError`; `oledcare.homeWant` is Home's ease while the panel draws it. `ctl paneldim` shows it, `ctl paneldim want 0.8` asks the panel for 0.8 of the user's value until `ctl paneldim release` (the quick way to see the whole path). Journal lines: `paneldim: dimming the panel from N`, `paneldim: panel back at N (why)`, `paneldim: ... failed: ...`, `paneldim: off for 10 min`.

## Why on by default

A failure is not a visible regression: every way the call can fail (no bridge, refused, unreadable, HDR) ends with the GPU dim and the saver's own dim doing what they did before, and a put back that fails is retried, journaled and covered by the next compositor start and the helper. What it costs when it works: one settings write per unit step (at most 60 a saver session, 13 an idle Home), each persisted by LG's settings service. What is not known until the TV check: whether the write is visible (a flash, an OSD) and how the value maps to light (below). If either fails, `panelDim` ships off with one line in the theme.

The value is scaled linearly: `round(value x level)`. The GPU dim scaled the colour (gamma-encoded), which is a larger fall in light for the same number (0.85 is about 0.70 of the light), and the saver's block was drawn with ink scaled by the same number. The panel's own scale is LG's: 0.85 of the value is not known to be 0.85 of the light. The TV check measures it; the levels are the saver's and the care's own tokens (`dimTo`, `dimOverMin`) and are tuned there.

The steps below are as written before the run.

Use a picture mode in SDR (`filmMaker`). Note the value: Settings › Picture › OLED pixel brightness. `lumatv-compositor ctl status | jq .oledcare.panelDim` throughout.

1. Reply shapes. `luna-send -n 1 luna://com.webos.service.settings/getSystemSettings '{"category":"picture","keys":["backlight"]}'` answers `settings.backlight` (a string) and `dimension` with `pictureMode` and `dynamicRange`. Also with `"dimension"` copied from that answer (the journal recovery asks it so). If the compositor's bridge is refused the service, `panelDim.lastError` says so and `carries` is false (the GPU dim does the work): the check ends there.
2. The write, by hand: `ctl paneldim want 0.8`. `written` falls one unit a 2 s from the value to 0.8 of it; the panel visibly dims with no flash, no OSD, no flicker of the picture or the sound; Settings › Picture shows the lower value while it is down. `ls /var/lib/lumatv/paneldim.json` exists. `ctl paneldim release`: the exact value is back in one step within 0.3 s, the file is gone, the journal says `panel back at N`.
3. How the value maps to light. With a still test card, hold 1.0, 0.85, 0.7 and 0.4 and measure the screen (a phone's lux meter, or the TV's own `luminance` if the service has one). Compare with the GPU dim at the same numbers (`paneldim:false`, `oledcare` with `dimTo 0.85`): record both ratios here. If the panel falls more or less than the saver's own dim did at the same level, adjust `dimTo` (saver 0.4, Home 0.85) in the theme.
4. Saver. Saver on, `ctl shell` shows `saverState.carry` true and `level`; the block is drawn at its first brightness while `written` falls with `level` (20 minutes to 0.4, or `screensaver.dimOverMin` 1 for a short run). `ctl status` `oledcare.saver` true. Any key: the value is exactly back within 0.3 s, the saver ends, `restores` +1. `screensaver.dim` false: no dim at all.
5. Idle Home. `lumatv theme set '{"oledcare":{"enabled":true,"dimAfterMin":1,"dimOverMin":2,"stepSec":10}}'` on a Home with a still wallpaper (the moving wallpaper keeps it bright, as before): `homeWant` falls, `oledcare.dim` stays `[1, 1]`, `written` follows. `ctl scanout` / `stats` `direct` frames keep growing while dim (Home goes to the plane whole): compare with `panelDim` false, where `dim` falls and the frames are composed. A key: back at once.
6. Exits. While dim: an app opens (`want` rises: back); a video plays (`block` video: back, no new dim while it plays); standby (`gate.sh standby`: put back as it goes, `restores` +1, no `offrsCount` change); `lumatv-compositor ctl quit` and a `kill` (the value is back before the process ends, `ls paneldim.json` gone).
7. Crash. While dim: `kill -9 $(pidof lumatv-compositor)`; LG's compositor takes over. Within 45 s the helper's thread puts the value back (`log-helper`: `panel dim: the compositor is gone and left the panel dim`); the file is gone. Again, and this time let LumaTV's compositor start first: it puts it back from the journal at its start.
8. Their change. While dim, change the value from outside the compositor (a luna call, a phone): the next poll (within 20 s) finds it, the value stays theirs, the journal line says `changed by someone else`, no dim begins for 5 minutes.
9. HDR. Start an HDR10 and a Dolby Vision title (`dolbyHdrCinema`): `panelDim.block` video and no write; with Home or the saver up over an HDR input, `hdr` true and `written` null.
10. Failure. Turn the setting off in Settings (`panelDim` false): `carries` false within 2 s, Home and the saver dim their own picture, the value is back. Refuse the call (a bad luna ACL): `latchedSec` counts down from 600, one `off for 10 min` line.
11. Cost. `ctl wake reset`, 60 s on a still Home with the dim engaged, `ctl wake`: the tick rate matches the same run with `panelDim` off; `panelDim.writes` grows by one every `panelDimStepSec` during a ramp and `reads` by one every 20 s after it, nothing else.

## Resume here

- The compositor side is `compositor/crates/lumatv-compositor/src/paneldim.rs` (state machine, journal, the `impl State` glue), the saver's side `rustui/ui/src/system/saver/model.rs` (`panel_carry`, `level`), the helper's net `helper/app/src/paneldim.rs`. The wire between the compositor and the Rust shell is the `paneldim` topic (`{carry}`) one way and `ui_state.saverState.{level, carry}` the other.
- Not known: whether `getSystemSettings` takes `dimension` (only the journal recovery asks it; if the service ignores it the read is the current mode's and, when that differs, the recovery writes the user's value to the journal's dimension without comparing); the mapping of the value to light (step 3); the compositor's bus identity being allowed the write (step 1).
- Not done on purpose: a ramp back up (a rise is one write), a per-picture-mode floor, anything for the QML saver (it has no level to report).
- If step 2 flashes or the write is refused, ship `panelDim` off (`payload/theme/theme.json`, `oledcare.panelDim`, and `CARE_ON_BY_DEFAULT` in `rustui/ui/src/settings/pages/system.rs`, the QML row's `true`, `tests/test_oledcare.py` `ON_BY_DEFAULT`).
